# Adopt a selected composition

Source qualification and deployed-service acceptance are separate. Select exact
published framework and library revisions, then generate from the consuming
site's own explicit composition. The public starter is not an installed layout.

Before a retained update, compare the resolved provider settings, artifact names
and bytes, runtime identities, mounts, credentials, health checks and dependency
graph against the accepted source. Preserve explicit NIC slots, volume identities,
Compose project filenames and per-app service names. Cosmetic labels do not
rename state. Root filesystem data declarations do not create provider volumes or
authorize ownership changes.

Bind genuine admission evidence through the selected framework's closed evidence
contract. Keep raw proof text, hashes, group membership, holds and ordinary receipt
lineage intact. See [custody](coordinated-custody.md) and [secrets](secrets.md).
Synthetic examples supply neither native acceptance nor a commissioning waiver.

Run the [source checks](testing.md), required hosted checks and actual current
source review. The consuming site's protected CD still requires its normal trust,
state, recovery, queue, ownership and prerequisite gates. Source publication does
not authorize a merge, native execution, account adoption or hold release.

After authorized deployment, verify the actual service and its selected
integrations. Keep package/runtime health, DNS, TLS, routing, browser sign-in,
database operation and household acceptance distinct. A successful compiler,
fixture, workflow or status check establishes only its tested boundary.
